# 使用与运维

## 飞书消息

业务提醒以飞书应用身份发给 `FEISHU_NOTIFY_USER_IDS` 里的人（店铺报告可单独用 `STORE_REPORT_NOTIFY_USER_IDS`）。同一件事只发一次；发送失败由维护任务在 10 分钟后补发，超过 48 小时不再补。

| 消息 | 什么时候发 |
|---|---|
| 新订单、订单取消 | 收到订单推送，状态首次变化时 |
| 订单退款 | 财务任务发现新的退款入账，每笔一条 |
| 货件状态更新 | FBA/AWD 货件变为已发货、运输中、已送达、已登记入仓、接收中（已由物流商跟踪的货件不发“已发货/运输中”） |
| 物流动态 | 头程物流商的关键节点（开船、到港、预约送仓、签收）、预计到港推迟 2 天以上、异常动态（甩柜、转船、查验等）；每轮合并一条，同一件事只提醒一次 |
| 库存预警 | 断货风险首次出现、升级或恢复 |
| 跟卖、购物车 | 跟卖者出现即提醒、离开满 1 小时确认后提醒；购物车丢失立即提醒、重新持有满 1 小时提醒恢复 |
| 品牌冒用 | 发现品牌是本店、但不属于本店的 listing，每个站点每个 ASIN 一次 |
| 竞品价格 | 竞品价格变化、开始促销；大促期间每轮合并成一条；竞品清单变化时发汇总 |
| 广告预算 | 活动预算使用率超过 `AMS_BUDGET_WARNING_PERCENT` |
| 关键词跑飞 | 每期排查有跑飞的投放或搜索词时，合并一条 |
| 放款 | 放款发起、到账 |
| 流量预警 | 会话或转化率明显下降、以及恢复 |
| 店铺健康 | 账户健康变差、在售款变不可售或新增 ERROR 级问题、新的高退货率处理费 |
| 压货与仓储费 | 冗余库存进出、超龄附加费、低库存费，每月的超龄附加费预告 |
| 店铺报告 | 日报每天，周报周日，月报月末初版、次月 22 日定稿，年报同理；消息带中台报告页链接 |
| 自动邀评汇总 | 每期邀评结束 |

技术故障（函数报错、队列积压等）**不发飞书**，只发 SNS 邮件，见下文「告警」。

## 店铺中台

浏览器打开控制栈输出 `PortalUrl`，用飞书账号登录（只有 `PORTAL_ALLOWED_USER_IDS` 里的人能进）。

- **首页**：仿卖家后台首页的“全局快照”指标格（今日销售额、销量、订单，并与近 7 日同一时刻比快慢；付款与余额；广告；库存；货件；购物车与跟卖；广告账单），下面是商品绩效表和近 7 天动态。配置了 `PORTAL_FEISHU_BASE_URL` 时，带箭头的数字可以点开对应的飞书表。
- **报告页**：`/report/day/2026-10-08`、`/report/week/2026-W41`、`/report/month/2026-10`、`/report/year/2026`，可以前后翻期、切换周期。
- 中台只读：不写飞书表、不发消息、不改亚马逊。某个区块取数失败时保留上次的数据，并标明时间和原因。

## 手动任务

所有定时任务也都可以手动触发，另有几个只供手动调用的任务。调用方式（PowerShell）：

```powershell
[IO.File]::WriteAllText("$PWD\payload.json", '{"taskType":"competitor-refresh"}')
aws lambda invoke --region us-east-1 --function-name amzshop-prod-jobs --cli-read-timeout 900 --payload fileb://payload.json result.json
Get-Content result.json
```

payload 写进文件再用 `fileb://` 传，避免 PowerShell 改动 JSON 引号。耗时长的任务可以加 `--invocation-type Event` 异步执行，结果看日志或状态表。

| taskType | 作用 | 默认行为 / 写入条件 |
|---|---|---|
| `acceptance-probe` | 只读自检：飞书表结构、站点、广告 Profile、卖家 ID | 只读 |
| `order-repair` | 定向重刷 1–20 个订单，`{"cursor":{"orderIds":["…"]}}` | 写订单表，不发消息 |
| `competitor-refresh` | 立即按规则刷新竞品清单 | 只读预览；`"cursor":{"apply":true}` 才写并发汇总 |
| `competitor-prices` | 竞品比价 | 平时只有 14:00 那轮真正比价；`"cursor":{"force":true}` 强制比价 |
| `offer-subscription-setup` | 创建或删除跟卖通知订阅 | 只读预览；`apply` 创建、`remove` 删除 |
| `forwarder-tracking` | 查一轮物流商轨迹 | 加 `"dryRun":true` 只读预览，可用来确认三家接口能连通 |
| `forwarder-backfill` | 把全部物流商货件的轨迹回填进货件表（不受停止条件限制） | 只读预览；`apply` 才写，全程不发消息 |
| `ads-review` | 调价复盘数据包（快照、库存健康、SQP、调价记录） | 只读；`"cursor":{"skus":["…"]}` 只看部分 SKU |
| `ads-memory` | 把调价与复盘结论写回「广告调整记录」「SKU广告档案」 | 只读预览；`apply` 才写。输入格式见 `src/business/ads-review.ts` 的 `parseMemoryInput` |
| `store-report` | 回填历史报告，`{"cursor":{"mode":"backfill","from":"2026-10-01","to":"2026-10-07"}}` | 只读预览；`apply` 才写，不发消息 |
| `review` | 自动邀评（见部署说明第 9 步） | `dryRun` 只读预演 |
| `notification-resume` | 立即补发待发通知 | 维护任务每小时也会做 |

## 调广告的工作流

系统只出数据、不改广告：预算、出价、广告位加价、活动状态、否定词和竞价策略都由人在广告后台手动调整。

1. 每日广告任务把近 30 天的投放、搜索词、广告位报表、广告目录和逐 SKU 每日销售存进状态表快照（保留 21 天）。
2. 跑飞排查以最近一次已执行的调价日为锚点，每 3 个完整站点日查一期，只报启用中、3 天点击达到阈值且 0 单的投放与搜索词。
3. 复盘时调用 `ads-review` 拿数据包，结合目标 ACOS（毛利率 − 10 个百分点）和清货线（毛利率 < 10%）决定调整；在后台改完后，用 `ads-memory` 把调整与结论写回飞书，作为下次复盘的依据。

原项目由 AI 助手读数据包给建议、人确认后执行；数据包是 JSON，也可以自己读。

## 告警

告警全部走 SNS 邮件（部署时 `-AlertEmail` 指定的邮箱）。系统正常时不发邮件。

| 来源 | 触发条件 |
|---|---|
| CloudWatch 告警 | 订单/预算/价格函数报错；任一死信队列有消息；源队列最老消息积压超过 5–10 分钟；状态表写限流 |
| Jobs 异步调用最终失败 | 定时任务重试后仍失败 |
| 维护任务（每小时） | 下表的健康检查、孤儿任务、飞书表行数与调用额度、广告授权快到期；同一问题 12 小时内不重复 |

健康检查：每项任务最近一次成功距今超过下列时长即告警（正常等待不算故障）。

| 任务 | 时长 |
|---|---|
| 每日任务（货件、财务、订单校准、库存、竞品比价、广告、资金、流量、品牌冒用、报价订阅核验、店铺报告、账户健康报告、库存健康、SQP 任务） | 26 小时 |
| 每小时或更频繁的任务（价格、Buy Box、报价对账、物流轨迹、订单商品小计、店铺健康） | 3 小时 |
| 单家物流商（有货件要查时） | 6 小时 |
| 关键词跑飞排查 | 50 小时 |
| 竞品清单刷新（每 7 天） | 8 天 6 小时 |
| SQP 新一周数据 | 12 天 |
| 自动邀评（每 15 天） | 16 天 |

## 排障

- **日志**：CloudWatch Logs 的 `/aws/lambda/amzshop-<环境>-<函数>`。日志是结构化 JSON，只记模块、任务、阶段、数量、耗时和脱敏后的错误。
- **死信队列**：先修好原因，再在 SQS 控制台用“开始 DLQ 重驱动”（StartMessageMoveTask）把消息移回源队列。不要清空队列：订单、交易消息的业务副作用要靠它们重放补齐。
- **中断的任务**：任务断点存在状态表 `TASK#<taskType>` 分区。维护任务发现 20 分钟没有进展、也没有续跑计划的任务，会按原身份重排（1 小时内不重复，连续 3 次没有进展只告警）。
- **飞书额度用尽**（错误码 `99991403`，每月 1 日重置）：定时任务记失败但不重试，只发一封邮件；订单、预算消息留在队列里重试，最终进死信队列，额度恢复后重驱动即可。
- **暂停全部自动入口**：见部署说明「更新、暂停与回滚」。

## 飞书容量与额度

- 维护任务每天查一次多维表格各表的行数，单表达到上限（`FEISHU_TABLE_ROW_LIMIT`，默认 2 万行）的 80% 发一次邮件，90% 起每天提醒；到上限后该表新记录会写入失败，需要归档旧数据。
- 每个函数按北京日期、按模块记录成功的飞书调用次数，每月 1 日的首轮维护把上月用量汇总进邮件；配置 `FEISHU_MONTHLY_CALL_QUOTA` 后，本月用量达 80% 提醒。
