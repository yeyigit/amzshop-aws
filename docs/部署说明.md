# 部署说明

整个流程分两段：先在**自动入口关闭**的状态下把栈和代码发上去、做只读验收，确认无误后再打开自动入口（SQS 事件源与全部定时计划）。下面的示例以控制区 `us-east-1`、订单区 `us-east-2`、环境名 `prod` 为例，账号 ID 用 AWS 文档的占位号 `123456789012`。

## 准备清单

**AWS**

- 一个 AWS 账号，以及一个部署专用 IAM 用户。权限可参考 `infra/deployer-policy.json`：把里面的账号 ID、区域、栈名、源队列名换成你自己的。建议用户只设密码 + MFA，通过 `aws login` 或 IAM Identity Center 取临时凭证，不建长期访问密钥。
- 控制区建议用 `us-east-1`：北美的广告 Marketing Stream 推送来自该区，发布脚本要求预算队列与控制区同区。订单队列可以放在任意区。

**本机**

- Windows + Windows PowerShell 5.1（发布脚本按 5.1 编写）
- AWS CLI v2、Node.js 24、Git
- 代码必须在 Git 仓库里：发布脚本记录提交哈希，并拒绝发布有未提交改动的工作区。

**亚马逊 SP-API**

- 一个开发者应用（自用的私有应用即可），以及本店授权得到的 refresh token。
- 按用到的接口申请角色：订单、财务（含 Transfers）、FBA 库存与入库、AWD、Listings、目录、定价（竞争摘要、报价）、销售、报告、Data Kiosk、通知、邀评（Solicitations）、促销、品牌分析（SQP 需要品牌备案）。没开通的模块会在调用时报错，其余模块不受影响。

**亚马逊广告 API**

- 广告 API 应用的 client id / secret、refresh token，以及美国站的广告 Profile ID。
- 要用预算推送（`ams` 模块），需要在 Amazon Marketing Stream 订阅 `budget-usage` 数据集，目标是第 2 步建的预算队列。

**飞书（中国版，open.feishu.cn）**

- 一个企业自建应用：需要多维表格读写、以应用身份发消息、获取用户 user ID 的权限（以开放平台当前的权限名为准），并把应用加为多维表格的协作者。
- 一个多维表格，按下文「飞书多维表格」建表。
- 店铺中台（可选）还需要一个网页应用，用于飞书登录。

## 第 1 步：本地检查

```bash
npm ci
npm run check
```

`npm run check` 依次做类型检查、全部测试和构建，任何一步失败都不要往下走。

## 第 2 步：建两条源队列

| 队列 | 放在哪个区 | 谁往里发 | 访问策略模板 |
|---|---|---|---|
| 订单队列 | 任意区（订单栈会建在这个区） | SP-API 通知：`ORDER_CHANGE`、`TRANSACTION_UPDATE` | `infra/source-queue-policies/amzn-order-queue.json` |
| 预算队列 | 控制区 | Marketing Stream 的 SNS 主题（`budget-usage`） | `infra/source-queue-policies/adsbudget-usage-que.json` |

- 先把模板里的账号 ID、区域、队列名换成你的，再粘贴到队列的「访问策略」。模板只放行亚马逊官方发送方，不要改成 `Principal: *`。
- 如果队列名与模板不同，同时修改 `infra/deployer-policy.json` 里的源队列 ARN。
- 报价队列（`ANY_OFFER_CHANGED`）不用自己建，模板会在控制区创建 `amzshop-<环境>-offer-events`。

## 第 3 步：写入配置与密钥

所有参数都写在**控制区**的 SSM Parameter Store，前缀 `/amzshop/<环境>/`。函数实例对普通配置缓存 10 分钟、对密钥缓存 6 小时，改完配置约 10 分钟后生效。

### 密钥包

全部密钥合成一个 SecureString 参数 `/amzshop/prod/secrets/bundle/main`，内容是 `{键名: 值}` 的 JSON。用脚本逐个写入，值在终端隐藏输入，不经过命令行参数、不打印、不落盘：

```powershell
$env:AWS_REGION = "us-east-1"
node scripts/set-secret.mts CLIENT_ID --init
node scripts/set-secret.mts CLIENT_SECRET
node scripts/set-secret.mts REFRESH_TOKEN
node scripts/set-secret.mts ADS_CLIENT_ID
node scripts/set-secret.mts ADS_CLIENT_SECRET
node scripts/set-secret.mts ADS_REFRESH_TOKEN
node scripts/set-secret.mts FEISHU_APP_SECRET
```

- `--init` 只在密钥包还不存在的第一次需要。
- 已有的键要轮换时加 `--replace`；先写入新值、确认生效后再去吊销旧值。
- 加 `--dry-run` 只校验不写入。
- 脚本里的路径固定为 `prod` 环境，用其它环境名时修改 `scripts/set-secret.mts` 的 `BUNDLE_PATH`。

| 键 | 用途 |
|---|---|
| `CLIENT_ID`、`CLIENT_SECRET`、`REFRESH_TOKEN` | SP-API（LWA） |
| `ADS_CLIENT_ID`、`ADS_CLIENT_SECRET`、`ADS_REFRESH_TOKEN` | 广告 API |
| `FEISHU_APP_SECRET` | 飞书自建应用 |
| `PORTAL_FEISHU_APP_SECRET` | 店铺中台登录用的飞书网页应用（启用中台时） |

### 普通配置

每个配置一个 String 参数，名字是 `/amzshop/prod/config/<键>`：

```powershell
aws ssm put-parameter --region us-east-1 --type String --name /amzshop/prod/config/SP_API_SELLER_ID --value "<你的卖家 ID>"
```

核心配置：

| 键 | 说明 |
|---|---|
| `SP_API_SELLER_ID` | 本店卖家 ID。用于单店铺校验和跟卖判断 |
| `MARKETPLACE_IDS` | 站点 ID，逗号分隔，默认美国站 `ATVPDKIKX0DER` |
| `ADS_PROFILE_ID` | 美国站广告 Profile ID；多站点改用 `ADS_PROFILES_JSON` |
| `FEISHU_APP_ID` | 飞书自建应用的 App ID |
| `FEISHU_NOTIFY_USER_IDS` | 接收提醒的飞书 user_id，逗号分隔 |
| `FEISHU_BITABLE_APP_TOKEN_ORDERS` | 多维表格的 app token（多维表格网址 `/base/` 后面那一段） |
| `FEISHU_BITABLE_TABLE_ID_*` | 各张表的 table_id，见下一节 |

其余可选项见本文末尾「全部配置项」。

### 飞书多维表格

所有表放在同一个多维表格里，每张表的 table_id 写进对应配置：

| 配置键 | 表 | 写入方 |
|---|---|---|
| `FEISHU_BITABLE_TABLE_ID_ORDERS` | 订单表 | `order`、`finance`、`order-prices`、`order-reason`、`review` |
| `FEISHU_BITABLE_TABLE_ID_SHIPMENTS` | 货件表 | `shipment`、`finance`（货件费用）、`forwarder-tracking`（7 个「物流…」列） |
| `FEISHU_BITABLE_TABLE_ID_SHIPMENT_DETAILS` | 货件明细表 | `shipment` |
| `FEISHU_BITABLE_TABLE_ID_SKUS` | SKU信息表 | 只读 |
| `FEISHU_BITABLE_TABLE_ID_PROFIT_ESTIMATE` | 毛利润预估 | `pricing` |
| `FEISHU_BITABLE_TABLE_ID_INVENTORY_PARAMETERS` | 库存参数 | `inventory` |
| `FEISHU_BITABLE_TABLE_ID_INVENTORY_ALERTS` | 库存预警 | `inventory` |
| `FEISHU_BITABLE_TABLE_ID_FINANCE_LEDGER` | 账户其他资金流水 | `finance` |
| `FEISHU_BITABLE_TABLE_ID_ADS` | 广告预算表 | `ams` |
| `FEISHU_BITABLE_TABLE_ID_ADS_CAMPAIGN_DAILY` | 广告活动日报 | `ads-daily` |
| `FEISHU_BITABLE_TABLE_ID_ADS_DAILY_OVERVIEW` | 广告每日总览 | `ads-daily` |
| `FEISHU_BITABLE_TABLE_ID_ADS_CAMPAIGN_MONTHLY` | 广告活动月报 | `ads-retention` |
| `FEISHU_BITABLE_TABLE_ID_ADS_ALERTS` | 广告预警 | `ads-runaway` |
| `FEISHU_BITABLE_TABLE_ID_ADS_CHANGES` | 广告调整记录 | `ads-memory` |
| `FEISHU_BITABLE_TABLE_ID_ADS_PROFILES` | SKU广告档案 | `ads-memory` |
| `FEISHU_BITABLE_TABLE_ID_PAYOUTS` | 亚马逊放款 | `payouts` |
| `FEISHU_BITABLE_TABLE_ID_BALANCES` | 亚马逊余额快照 | `payouts` |

- **字段名以代码为准**：模块写入飞书的对象键就是字段名，例如订单表字段见 `src/business/orders.ts`、`finance.ts`，货件表见 `shipments.ts`。人工维护的字段（如货件表「承运商」、毛利润预估里的成本与公式）程序只读不写。
- 订单表的「金额」、毛利润预估的「毛利」「活动价毛利润」必须是公式字段。
- 要用物流轨迹（`forwarder-tracking`）时，货件表另建 7 列：「物流节点」（单选）、「物流最新动态」「物流商单号」（文本）、「物流轨迹」（多行文本）、「物流预计到港」（日期）、「物流签收时间」「物流同步时间」（日期时间）。「承运商」由人工填写，含“纽酷”“九方”“美设”就按对应物流商查，为空时三家都查。缺列时任务报错并指出缺哪一列。
- 用不到的模块可以不建对应的表，但要关掉该模块的开关或不打开它的计划。
- 第 5 步的只读自检会核对订单、毛利润预估、库存参数、库存预警、货件、SKU信息表的必需字段。

### SKU 与 ASIN

每个 SKU 一个参数 `/amzshop/prod/asin/<名字>`，值是 JSON。参数名只能含字母、数字和 `_ . -`，程序以值里的 `sku` 为准：

```powershell
[IO.File]::WriteAllText("$PWD\sku.json", '{"sku":"SKU-001","asin":"B0XXXXXXXX","competitors":[],"adMarker":""}')
aws ssm put-parameter --region us-east-1 --type String --name /amzshop/prod/asin/SKU-001 --value file://sku.json
```

- `competitors`：人工指定的竞品 ASIN，永远保留并计入竞品上限。
- `adMarker`：广告活动名里含这个标记的活动归到该 SKU（广告预算表的「所属SKU」）。

## 第 4 步：首次部署（自动入口保持关闭）

先 `git commit`，再执行：

```powershell
npm run deploy -- -Region us-east-1 `
  -OrderQueueArn "arn:aws:sqs:us-east-2:123456789012:amzn-order-queue" `
  -OrderQueueUrl "https://sqs.us-east-2.amazonaws.com/123456789012/amzn-order-queue" `
  -AmsQueueArn "arn:aws:sqs:us-east-1:123456789012:adsbudget-usage-que" `
  -AmsQueueUrl "https://sqs.us-east-1.amazonaws.com/123456789012/adsbudget-usage-que" `
  -AlertEmail "you@example.com"
```

脚本会：校验工作区干净与队列 URL/ARN 一致 → 跑 `npm run check` → 部署控制栈与订单栈 → 上传 6 个函数的代码并发布版本 → 把部署记录写到 `artifacts/deployments/` 和 `artifacts/deployment-manifest.json`（`artifacts/` 已在 `.gitignore`，里面有账号 ID，不要提交）。

- 新栈的 `AutomationState` 默认是 `DISABLED`：SQS 事件源和全部定时计划都不启用。之后的发布默认保持现状（`PRESERVE`）。
- 两个区各会发来两封 SNS 订阅确认邮件（告警、投递失败），记得点确认。
- 其它参数：`-StackName`、`-OrderStackName`、`-Environment`、`-Profile`、`-Functions jobs,portal`（只发部分函数）、`-SkipStacks`（只更新代码不动栈）、可选的独立价格队列 `-PricingQueueArn`/`-PricingQueueUrl`。`-AllowDirty` 只用于应急，会记录未提交改动的补丁，事后要补提交并重新发布。

## 第 5 步：源队列保护与只读验收

**源队列保护**（控制台或 CLI 设置）：

| 队列 | 消息保留期 | 可见性超时 | 死信队列 |
|---|---|---|---|
| 订单队列 | 7 天 | 不少于 30 分钟 | 订单栈输出 `OrderDlqArn`，最大接收次数 5 |
| 预算队列 | 7 天 | 不少于 12 分钟 | 控制栈输出 `AmsDlqArn`，最大接收次数 5 |

**只读自检**：调用一次 Jobs 函数的 `acceptance-probe` 任务，它只读飞书表结构、亚马逊站点、广告 Profile 和卖家 ID，不写任何东西：

```powershell
[IO.File]::WriteAllText("$PWD\payload.json", '{"taskType":"acceptance-probe"}')
aws lambda invoke --region us-east-1 --function-name amzshop-prod-jobs --cli-read-timeout 900 --payload fileb://payload.json result.json
Get-Content result.json
```

返回 `"status": "done"` 才继续。

## 第 6 步：订阅亚马逊推送

- **订单与交易**：用 SP-API Notifications API 为订单队列创建目的地（destination），再订阅 `ORDER_CHANGE` 与 `TRANSACTION_UPDATE`。本仓库没有附带这一步的脚本。
- **跟卖与购物车**：用内置任务创建 `ANY_OFFER_CHANGED` 的目的地与订阅（按第 5 步的方式调用 Jobs 函数）。默认只读预览，确认后带 `apply` 再跑一次：

  | 步骤 | payload |
  |---|---|
  | 预览 | `{"taskType":"offer-subscription-setup"}` |
  | 创建 | `{"taskType":"offer-subscription-setup","cursor":{"apply":true}}` |
  | 删除 | `{"taskType":"offer-subscription-setup","cursor":{"remove":true}}`（只删指向本功能报价队列的订阅） |
- **广告预算**：在 Amazon Marketing Stream 订阅 `budget-usage`，目标为预算队列。

## 第 7 步：打开自动入口

```powershell
npm run deploy -- <第 4 步的同一组参数> -AutomationState ENABLED
```

打开后，SQS 事件源开始消费，22 个定时计划开始按时触发。第一天留意邮件告警和飞书消息。

## 第 8 步（可选）：店铺中台

1. 中台网址是控制栈的输出 `PortalUrl`（Lambda 函数网址）。首次打开会显示需要填进飞书网页应用的「主页地址」和「重定向 URL」。
2. 在飞书开放平台建网页应用，填好这两个地址，开通获取用户 user ID 的权限并发布版本。
3. 写配置：`PORTAL_FEISHU_APP_ID`（普通配置）、`PORTAL_FEISHU_APP_SECRET`（密钥包）、`PORTAL_ALLOWED_USER_IDS`（允许登录的飞书 user_id，逗号分隔）。
4. 可选：`PORTAL_FEISHU_BASE_URL`（多维表格网址，形如 `https://<租户>.feishu.cn/base/<app token>`）让页面上的数字可以点开对应的飞书表；`PORTAL_FEISHU_LINKS` 改某个数字指向的表或视图；`PORTAL_TITLE` 改页面标题。店铺报告消息里的中台链接由模板自动注入（Jobs 的环境变量 `PORTAL_URL`），不用配置。

登录态是用应用密钥派生签名的 `__Host-` Cookie；不在白名单里的账号登录后只会看到自己的 user_id 和开通说明。

## 第 9 步（可选）：自动邀评

邀评按 15 天一期自动续排，锚点是 `src/business/reviews.ts` 里的 `REVIEW_ANCHOR_MS`（默认北京时间 2026-09-15 01:00），可以改成你想要的起点。

1. 先只读预演（不发送、不改计划，taskId 不能用正式锚点的格式）：

   ```json
   {"taskType":"review","taskId":"review-dry|1","dryRun":true,"cursor":{"maxCandidates":20}}
   ```

2. 确认后，用最近一个已过去的锚点时刻手动触发一次正式批次，它会自己排好下一期：

   ```json
   {"taskType":"review","taskId":"review|2026-09-14T17:00:00.000Z","scheduledAt":"2026-09-14T17:00:00.000Z"}
   ```

正式批次会真实发出邀评请求。请求结果不明时只记“未知”、永不重发。

## 更新、暂停与回滚

- **更新**：提交后 `npm run deploy -- <参数>`，自动入口保持现状。
- **暂停全部自动入口**：`npm run deploy -- <参数> -AutomationState DISABLED`；或 `scripts/cutover.ps1 -Phase PauseAws <队列参数>`，只改 `AutomationState`、不发代码。
- **测试告警链路**：`scripts/cutover.ps1 -Phase AlertTest <队列参数>`，往两个区的告警主题各发一封测试邮件。
- **回滚代码**：检出旧提交后重新发布。每次发布的版本号、提交哈希和包哈希都在部署记录里。

| 键 | 默认 | 关掉后 |

| `COMPETITOR_SALE_MODE_ENABLED` | 开 | 竞品比价恢复每天一轮、逐条通知 |

| `FORWARDER_TRACKING_ENABLED` | 开 | 物流轨迹空跑（不调接口、不写表），亚马逊“已发货/运输中”提醒恢复照发 |
